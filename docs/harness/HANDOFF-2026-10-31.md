## 六、环境纪律速查（踩过的坑，反复生效）

- PostgreSQL：`pg_ctl -D /opt/homebrew/var/postgresql@15 -l /tmp/pg-startup.log start`（socket /tmp）。真源库 `clair`。
- 后台服务**必须用 Bash 工具 `run_in_background:true`**；shell `&` 起的服务被沙箱禁外网。
- 本地探测必须 `curl --noproxy '*'`（回环会被 HTTPS_PROXY 拦成 502）。
- 沙箱 `grep` 是坏 shim → **一律 `rg`**。
- 全量 `tsc --noEmit` / vitest / `vite build` 会 OOM 出假错 → 语法校验用 `esbuild <file> --bundle --packages=external --loader:.tsx=tsx --format=esm --outfile=/dev/null`；`vite build` 必须 `--outDir /tmp/xxx`。
- 端口纪律：共享 3001 常驻；新实例用独占高位端口；**禁止 `pkill -f "tsx src/index.ts"`**（已误杀共享实例）。
- git push 失败先**去掉全部 proxy 变量直连重试**：`env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY -u all_proxy -u ALL_PROXY git push origin main`。
  ⚠️ **2026-11-01 更正（原条目写反了）**：原文写「502 是代理抽风，`git config http(s).proxy "$HTTPS_PROXY"` 后重试即过」——实测**走代理才是 502 的主因**（`CONNECT tunnel failed, response 502`）。
  不要配 git proxy；若曾被配过要清掉：`git config --unset http.proxy; git config --unset https.proxy`。
  直连仍失败时用兜底通道：`node scripts/git-push-api.mjs`（Git Data API，含内容级校验），详见本节末条。
- `/api/cron/collect-history` 是 **Worker 专属**（Express 零命中，靠 KV `STOCK_DATA`），切 Render 时禁止改其域名。
- `VITE_API_BASE` 三处：`deploy.yml:40`、`ci.yml`、`frontend/src/main.tsx`（无 fallback，缺失即中止启动）。
- 数据源：腾讯财经 `proxy.finance.qq.com` 本机稳定；**东财 push2 间歇不可达（HTTP 000）**。
- **推送通道判定顺序（2026-11-01 实测定案，与上一条 182 行的「先设 proxy 再重试」相反，以本条为准）**：
  ①**先去 proxy 直连重试**（代理路径多数时候报 `CONNECT tunnel failed, response 502`，设 proxy 只会更坏；注意两个方向都是间歇故障，单次成功/失败都不能当定论）：
  `env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY -u all_proxy -u ALL_PROXY git push origin main`
  ②①失败再跑 `node scripts/git-push-api.mjs`（Git Data API 逐提交重建，零依赖）；
  ③两者都失败**才**上报，且必须贴失败原文，不许假装成功。
  配套三条纪律：**(a)** API 推送会重建 commit 对象 ⟹ 远端 sha 必然与本地不同，父链不同时 tree hash 也可能不同；**(b)** 因此「内容是否落地」只能用**文件级比对**（逐 path 比 blob sha / 文件 shasum），**绝不能拿 commit sha 或 tree hash 当判据**；**(c)** 推送成功后**必须** `git update-ref refs/remotes/origin/main $(git rev-parse HEAD)`（只能指向本地 commit），否则本地 origin/main 持续落后，后续"有没有未推送"的判断全部错位（曾因此产生空提交）。详见 `TICKET-LEDGER.md` 105-132 行。
- 用 JS `Date` 作 `trade_date` 等 `date` 列的查询键时，knex 按**本地分量**渲染 SQL 字面量；因此 UTC 零点 Date 在负偏移时区会落到前一天。查「某个日历日」请用该日的本地零点（后端统一用 `tradingCalendar.localDayKey('YYYY-MM-DD')`，或直接传 `YYYY-MM-DD` 字符串），不要传 `new Date('YYYY-MM-DDT00:00:00Z')`。
