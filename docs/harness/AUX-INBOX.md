## 一、这条信道解决什么问题

主导方自己 commit、自己验收，项目已多次实锤「自报完成 ≠ 真的可用」。
本文件让主导方可以把「**我拿不准、或风险最高**的那几条」显式派给辅助方做对抗性复验，
而不是等用户在自己脸上发现。

**不必每批都派。** 建议只派三类：
1. 新增了门禁/断言（门禁本身可能是假的——历史上曾有「测试自己测自己」）；
2. 声称「接线完成 / 已挂载 / 已生效」的改动（死代码高发区）；
3. 诚实红线相关（`dataSource` 三态、`null` 与 `0` 的边界）。

## 二、条目格式

```
### [AUX-YYYYMMDD-N] <一句话标题>
- 批次：<commit 范围或 hash>
- 声明：<可被证伪的具体断言，不要写「完成了 X 模块」>
- 复验要求：<四证中的哪几条 / 我特别怀疑哪里>
- 期限：<相对时间>
```
