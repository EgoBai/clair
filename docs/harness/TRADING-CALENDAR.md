# 交易日历数据源与维护

> 对应实现：`backend/src/utils/tradingCalendar.ts`
> 跨年校验：`backend/src/__tests__/tradingCalendarHypothesis.node-test.ts`

本文说明交易日历的**权威来源、精度等级、更新流程**，供后续维护者核对。

---

## 一、设计决策：为什么「内置日历」而非「从数据库反推」

本项目`daily_quotes` 有 5544 只股票的真实日线，表面上最可靠的「交易日来源」是
`SELECT DISTINCT trade_date FROM daily_quotes ORDER BY trade_date DESC LIMIT 1`。
**实测证明这条路不可用**（详见 `anti-patterns.md` AP-2）。

### 抹布行实测证据

```sql
SELECT trade_date, COUNT(*) FROM daily_quotes
 WHERE trade_date >= '2026-09-18' GROUP BY trade_date ORDER BY trade_date DESC;
```

| trade_date | 星期 | rows | 真实性质 | 日历判定 |
|---|---|---|---|---|
| 2026-10-07 | 三 | 5541 | 国庆休市 | 非交易日 |
| 2026-10-06 | 二 | 5541 | 国庆休市 | 非交易日 |
| 2026-10-05 | 一 | 5541 | 国庆休市 | 非交易日 |
| 2026-10-04 | 日 | 5541 | 周末 | 非交易日 |
| 2026-09-25 | 五 | 5541 | 中秋休市 | 非交易日 |
| 2026-09-24 | 四 | 5541 | **真实交易日** | 交易日 |
| 2026-09-22 | 二 | 5541 | **真实交易日** | 交易日 |
| 2026-09-30 | 三 | **0** | **真实交易日** | 交易日（库中无数据） |

关键佐证：贵州茅台 `600519.SH` 在 10-04/05/06 三天 OHLCV **完全相同**
（close 1258.62 / volume 38331）——「把上一交易日值复制到假期日期」的抹布特征。

结论：若以库内最大日期为权威，`latestTradingDay('2026-10-06')` 会返回
`'2026-10-06'` 且 `isFallback: false`，**在法定休市日告诉用户「这是今天的行情」**。

### 采用的方案

**内置交易所公告为权威 + PG 交叉校验（只优选、不否定）**

| 层 | 角色 | 说明 |
|---|---|---|
| ① 交易所公告休市表 + 周末规则 | **权威** | 纯函数、不查库、结果稳定可测 |
| ② PG `DISTINCT trade_date` | 交叉校验 | 只在日历已认可的日期里做优选；**绝不**反向否定公告 |
| ③ PG 不可达 | 降级 | 用内置表推算，note 显式声明精度来源 |

判定「交易日」必须同时满足：`isTradingDay(d) === true` **且** `库中确有该日行情`。
只做前者会把抹布行当行情上报；只做后者会把休市日当数据日。

## 二、数据源与精度等级

| 年份 | 来源 | `precision` | 交易日数 | 公告发布时间 |
|---|---|---|---|---|
| 2025 | 沪深北交易所公告原文 | `official` | 243 | 2024-12-23 |
| 2026 | 沪深北交易所公告原文 | `official` | 242 | 2025-12-22 |
| 2027 | **公告未发布**，按国务院法定节假日推导 | `provisional` | 239 | **待发布** |
| 其他 | 无内置表，仅周末规则 | `unavailable` | — | — |

### 2026 年休市安排（公告原文）

| 节日 | 休市区间 | 交易日节后首日 |
|---|---|---|
| 元旦 | 01-01(四) ~ 01-03 | 01-05(一) |
| 春节 | 02-15(日) ~ 02-23(一) | 02-24(二) |
| 清明节 | 04-04(六) ~ 04-06(一) | 04-07(二) |
| 劳动节 | 05-01(五) ~ 05-05(二) | 05-06(三) |
| 端午节 | 06-19(五) ~ 06-21 | 06-22(一) |
| 中秋节 | 09-25(五) ~ 09-27 | 09-28(一) |
| 国庆节 | 10-01(四) ~ 10-07(三) | 10-08(四) |

算术自洽校验：2026 共 **261 个工作日** − **19 个法定休市工作日** = **242 交易日**。

### 2025 年休市安排（公告原文）

元旦 01-01；春节 01-28 ~ 02-04；清明 04-04~ 04-06；劳动节 05-01 ~ 05-05；
端午 05-31 ~ 06-02；国庆+中秋 10-01 ~ 10-08。
自洽校验：261 个工作日 − 18 个法定休市工作日 = **243 交易日**。

### 2027 年（临时表，`provisional`）

⚠️ 交易所历年于头一年 12 月中下旬发布次年安排，**2027 年公告尚未发布**。
下表按国务院 2027 年法定节假日 + A 股惯例推导，**不是公告原文**：

| 节日 | 推导区间 |
|---|---|
| 元旦 | 01-01(五) ~ 01-03 |
| 春节 | 02-05(五) ~ 02-11(四) |
| 清明节 | 04-03(六) ~ 04-05(一) |
| 劳动节 | 04-30(四) ~ 05-05(三) |
| 端午节 | 06-09(三) ~ 06-11 |
| 中秋节 | 09-15(三) ~ 09-17 |
| 国庆节 | 10-01(五) ~ 10-07(四) |

**已知不确定项**（公告发布后必须逐项核对）：

- 春节 02-06 为周六，02-05(五) 与 02-11(四) 是否休市取决于调休安排
- 劳动节 05-01 为周六，05-04(二) 是否补休取决于官方安排
- **元旦 01-04(一) 是否休市存疑**：现按「01-01~01-03 休市、01-04 上班」取值。
  若官方安排调休，该日应休市，交易日数将由 **239 变为 238**

该差异由 `tradingCalendarHypothesis.node-test.ts` 主动打`::warning::` 暴露。

### 诚实红线

查询 2027 或未覆盖年份时，`resolveQueryDate()` 的 note 会**显式声明**
「尚未发布…按法定节假日推导（近似）」/「仅按周末规则推算（精度较低）」。

**绝不静默假装全年精确，也绝不安静地把不确定性当成错误让构建变红**
（前者是失真，后者会导致大家把标注删掉）。

## 三、更新流程

每年 **12 月中下旬**交易所公告发布后：

1. 用公告原文替换 `HOLIDAY_RANGES_<年>` 的区间与节日名
2. 把 `BUILTIN_CALENDARS[<年>].precision` 从 `'provisional'` 改为 `'official'`
3. 同步更新 `tradingCalendarHypothesis.node-test.ts` 中该年的
   `EXPECTED_TRADING_DAYS` 与 `MUST_BE_CLOSED`
4. 更新 `tradingCalendar.test.ts` 中对应年份的休市日断言
5. 核对算术自洽：`<年>工作日数 − 法定休市工作日数 === 交易日总数`
6. 跑双源校验确认无新 `::warning::`：

```bash
cd backend && DATABASE_URL="postgresql://..." \
  node --import tsx --test src/__tests__/tradingCalendarHypothesis.node-test.ts
```

> 注：交易所每年**可能临时调整**（如临时休市、紧急公告）。
> 若某日实际休市但内置表未含，候选窗口会因库中无数据而自动回退到更早的交易日，
> 并在 note 中如实说明；不会把不存在的行情展示给用户。

## 四、参数取值依据

### `CANDIDATE_LOOKBACK_TRADING_DAYS = 20`（交易日，非日历日）

- A 股最长法定长假为 9 个连续休市日（国庆 10/01–10/07，含调休）
- 数据滞后（如节后未同步）会额外拉长窗口
- 取 **≥ 2× 最长法定长假**，避免长假期间窗口耗尽导致 `isFallback`频繁误报
  —— 误报会让上层不再信任该标志，**从而失去诚实约束能力**

代价：窗口越大，越可能回退到「更早但确有数据」的日期。
这是**刻意选择** —— 宁可让用户看到稍旧但真实的数据，也不展示当天并不存在的行情。

## 五、对账口径

`reconcileCalendarWithQuotes()` 把窗口内交易日历与库内实际数据分为三类：

| 分类 | 含义 | 处理 |
|---|---|---|
| `corroborated` | 日历说有、库也有 | 强证据，可用 |
| `missingInDb` | 日历说有、库无 | 可能停市或数据未同步 → 回退 + note 说明 |
| `smearedInDb` | 库有、日历说非交易日 | **伪造行**，绝不可作为行情上报 |

当前实测：佐证 24 天 / 日历有库无 79 天 / 抹布 17 天（区间 2026-08-03~ 12-31）。

库中抹布行总数 **23 个**（可用 `detectSmearedQuoteDates()` 复查）。
这些是数据源层面的问题（本工单只做识别与隔离，不负责清洗），
建议由数据同步链路排查。

## 六、调用方须知

```ts
const q = await resolveQueryDate(req.query.date as string | undefined);
send(res, { data: rows, asOfDate: q.date, isFallback: q.isFallback, note: q.note });
```

- **必须**在响应里透出 `q.date`（数据截至哪天）与 `q.isFallback`（是否回退）
- `isFallback === true` 时应把 `q.note` 展示给用户，而非静默替换
- **不得**把 `q.date` 渲染成「今天」/「实时」
- 纯展示类数据（新闻、事件日历、订阅推送）**不应**接入本模块 ——
  它们在休市期仍是真实发生的，回退会造成新的失真
