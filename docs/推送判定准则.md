# 推送判定准则：只看内容，不看 sha

本仓 `git push` 常年因 `github.com:443` 不可达失败，改走 `scripts/git-push-api.mjs`
（Git Data API：blob → tree → commit → ref）。以下三条判据固定不可信：

| 判据 | 为什么不可信 |
| --- | --- |
| 远端 sha == 本地 sha | API 会**重建 commit 对象**（父链/committer 不同），sha 必然不同；相同才是巧合。 |
| `git rev-list --count origin/main..main` | 比的是本地 `refs/remotes/origin/main`，它由脚本 `update-ref` 对齐。脚本没跑或半途失败时这个数字只会骗人。 |
| tree hash 相同 | 同样受重建影响；且只比 blob sha 会漏掉 **mode**（可执行位/符号链接位）差异。 |

## 唯一可信判据：逐文件 (mode, blob sha) 全等

本地 `git ls-tree -r <commit>` ↔ 远端 `GET /git/trees/<tree>?recursive=1`，逐 path 比 mode 与
blob sha。两侧同算法（`sha1("blob <len>\0" + content)`），是精确比对而非近似。脚本输出一行结论：
`CONTENT_CHECK=OK files=<N> baseline=<本地 commit>`，或 `CONTENT_CHECK=FAIL` + 逐条差异明细。

```bash
node scripts/git-push-api.mjs            # 真推
node scripts/git-push-api.mjs --dry-run  # 只算差异，一个写请求都不发
GPA_BRANCH=main GPA_REMOTE=origin node scripts/git-push-api.mjs
```

判成功要**同时**满足：`echo $?` 为 0，且输出里有 `CONTENT_CHECK=OK`。exit 0 的每条路径都必定
先打印这一行（含「无待推送」「提交全为空」两种早退）；「没有 FAIL 就当过」不成立。
## 退出码

- `0` 内容一致（推成功 / 本来就一致）；`2` `PUSH_ABORTED` 远端被别人推进，未覆盖（未写）。
- `1` `PUSH_FAILED`，或 `CONTENT_CHECK=FAIL`。**FAIL 发生在 PATCH 之后**：远端分支**已经被改**，
  脚本不回退（force 回退更危险），并把本地 `origin/main` **故意留旧** —— 必须人工介入，别当「没推上去」重跑。

## 无写入自检（怀疑通道坏了先跑，一个新提交都不产生）

```bash
git clone --shared . /tmp/cc && cd /tmp/cc && git reset --hard origin/main  # 内容与远端一致
node scripts/git-push-api.mjs   # 期望 CONTENT_CHECK=OK + NOTHING_TO_PUSH + exit 0，零写请求
```

脚本不使用临时 ref（只在最后 PATCH 目标分支一次），故中止时没有「自建 ref 残留」，
只留若干不可达 blob/tree/commit，GitHub 自行回收，不影响分支。
