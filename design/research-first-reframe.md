# 澄观 Clair 产品方向重构建议：从行情终端到研究工作台

状态：方向已确认（2026-11-05），P0 待实施；P1 在 P0 验收后启动。编制时间：2026-11-05。配套文档：`DESIGN.md`。

本文回答三个问题：是否转向投研信息整合与 AI 分析助手；如果转，产品、信息架构与体验怎么改；商业化与小程序怎么接。所有结论先评审，不直接改代码。

## 一、判断

一、应该转，但不是“砍掉行情”。行情与资金数据是研究的上下文，不能丢；要改的是产品重心：从“全市场监控 + 指标堆叠”转为“把一家公司研究透的工作台”。

二、当前产品的能力不弱，弱在闭环。31 个路由页面覆盖行情、资金、财务、产业、研报、组合、回测，真实数据已基本接通；但用户完成一次研究的路径是断的：研报不链个股，个股没有研报/公告 tab，笔记不挂个股，AI 不知道当前页面数据是否可用。

三、继续按“再加一个页面、再加一个指标”推进会越做越像数据终端。终端赛道的对手是 Wind、同花顺、东方财富，个人产品在数据广度与速度上没有胜算；胜算在“研究过程的组织与记忆”。

四、AI 不是差异化本身。模型能力在商品化，数据接口也在商品化；可积累的是“证据化的研究过程”：用户看过什么、得出什么结论、后来被什么证伪。这个资产越用越厚，才是壁垒。

五、因此建议的定位是：**研究工作台优先，行情监控作为上下文，AI 作为有证据边界的分析助手**。不是转成“AI 聊天软件”，也不是转成“极简看盘工具”。

## 二、目标用户与核心任务

| 项 | 判断 |
| --- | --- |
| 核心用户 | 进阶个人投资者、小机构研究员、独立研究员；每周研究 3–10 家公司，持有 10–30 只跟踪标的 |
| 非目标 | 高频交易者、纯盯盘用户、量化机构；这些用户要的是速度、Level-2、交易通道，不是研究闭环 |
| 核心任务 | 在 20 分钟内把一家公司从“看到线索”推进到“有可复盘的研究结论” |
| 现有替代 | 东方财富/同花顺看数据，雪球看观点，Excel/Notion 记笔记，ChatGPT 做总结；切换成本高、证据不连贯 |
| 我们的机会 | 把数据、证据、结论、跟踪放在同一条时间线上，AI 在每一步补上下文而不是另开一个聊天窗口 |

## 三、定位与价值主张

一句话定位：**澄观是一个能陪你把一只股票研究透的 AI 投研工作台。**

价值主张不是“数据全”，而是三件事：

| 价值 | 具体含义 | 可验证的体验 |
| --- | --- | --- |
| 省时间 | 把分散在 6 个页面的公司信息收成一张研究卡 | 打开个股，一屏看到身份、估值、财务变化、产业位置、近期事件、已有结论 |
| 有证据 | 每个 AI 结论都能点回数据块与日期 | 结论下方列出证据卡；数据不可用时明确说“不能判断” |
| 能积累 | 研究结论、假设、复盘留在标的上 | 每只股票有研究笔记与观点时间线，下一次打开能接着上次 |

## 四、研究循环

目标产品围绕一个五步循环，而不是围绕页面清单：

| 步骤 | 用户动作 | 产品能力 | 当前对应 |
| --- | --- | --- | --- |
| 1 发现 | 今天有什么值得看 | 首页线索、筛选、雷达、事件日历 | 已有，但线索之间无优先级 |
| 2 建档 | 这家公司是什么、贵不贵 | 公司一页纸：业务、财务、估值、产业位置、股东、事件 | 分散在个股、财务、估值、产业、股东页面 |
| 3 验证 | 我的判断站得住吗 | 同业对比、产业链、研报、资金流、历史事件类比 | 页面都有，但不互链 |
| 4 结论 | 我到底怎么看 | 观点卡：多空、催化、风险、估值区间、置信度、证据 | 只有自由文本笔记，无结构 |
| 5 跟踪 | 什么变化会推翻我 | 事件提醒、观点复盘、证伪条件、周报 | 自选有行情，无观点跟踪 |

AI 在五步中的角色：发现时排序线索，建档时压缩财报与公告，验证时找反例，结论时检查逻辑漏洞，跟踪时提示“与你的假设不一致的新事实”。不是替代用户下结论，而是让结论更有依据。

## 五、现状差距

| 差距 | 事实 | 后果 |
| --- | --- | --- |
| 没有研究结论的载体 | `KnowledgeBase.tsx` 是独立本地笔记，不挂个股；个股页无笔记入口 | 研究完就散，下次从零开始 |
| 研报与个股断开 | `ReportCenterPage.tsx` 全文无 `navigate/Link`；个股页无研报/公告 tab | 看到研报无法回到公司 |
| 数据可信度未进入 AI | `FloatingChat.tsx:48-72` 只有 7 类页面上下文，`:307` 未注入 dataSource；数据 unavailable 时仍分析 | AI 可能在没有数据时给结论 |
| 诚实判定覆盖不足 | 33 个页面组件只有 12 个真正读 `dataSource` 并改变渲染 | 角标是装饰，失败时像正常 |
| 页面按数据源分组 | 6 个导航组 3/7/10/2/3/1 项；组合风控在“宏观资金” | 用户按任务找不到入口 |
| 图表默认过载 | 个股页多指标、多面板同时出现 | 首屏噪声，研究结论被压到第三屏 |
| AI 后端不稳定 | `/api/ai/diagnose` 返回 `unavailable`（`DEEPSEEK_API_KEY` 未配置）；`/api/ai/gems`、`/api/ai/strategy-recommend` 线上 404 | 依赖 AI 的页面无法作为产品主轴 |

结论：不是缺页面，是缺“把页面连起来的那条线”。下一个版本应该减少页面，而不是增加页面。

## 七、前端体验重构

### 7.1 个股页：从指标面板改为研究卡

首屏顺序调整为：

一、公司身份：名称、代码、行业、一句话业务、当前价与涨跌。

二、当前判断：估值位置、财务趋势、产业位置、近期事件，四个结论句，不是四张指标卡。

三、研究操作：加入自选、写观点、看研报、问 AI。

四、证据区：K 线、财务、估值、资金、公告，折叠在下方。

K 线默认只保留价格、成交量、MA5/MA20 与事件标记；MACD、KDJ、BOLL 等收进“更多指标”。这不是删功能，是降低首屏噪声。

### 7.2 公司一页纸

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| 身份 | 名称、代码、行业、上市板、主营业务 | `/api/stocks/:symbol`、`/api/valuation/:symbol` |
| 估值 | PE/PB/PEG、三年分位、DCF 区间 | `/api/valuation/:symbol` |
| 财务 | 营收/利润/ROE/现金流趋势、同比 | `/financials/*` |
| 产业 | 所属产业链、上下游、同业 | `/api/industry-chains`、`/compare` |
| 事件 | 解禁、财报、股东大会、研报 | `/api/lockup/calendar`、`/api/news/research/reports` |
| 我的观点 | 多空、催化、风险、证伪条件、置信度 | 新增本地/后端研究模型 |

### 7.3 观点卡

这是新产品最关键的组件，也是当前完全缺失的：

| 字段 | 说明 |
| --- | --- |
| 标的 | 股票代码与名称 |
| 结论 | 看多 / 中性 / 看空 / 观察 |
| 核心逻辑 | 三句话以内 |
| 催化 | 未来 3–12 个月可能发生的事 |
| 风险 | 什么会让逻辑失效 |
| 证伪条件 | 可观测的指标或事件 |
| 估值区间 | 买入/合理/卖出区间，可空 |
| 置信度 | 低 / 中 / 高 |
| 证据 | 链到数据块、研报、笔记 |
| 复盘 | 每次更新记录“什么变了” |

观点卡不要求用户一次填完；AI 可以从笔记和当前数据生成草稿，但必须由用户确认。

### 7.4 视觉与交互

| 项 | 建议 |
| --- | --- |
| 风格 | 保留暗色金融终端，但减少装饰性渐变与卡片边框，强化字号层级与留白 |
| 密度 | 概览页高密度；研究页中密度；观点与笔记低密度、15px/1.75 行高 |
| 状态 | 统一 loading / empty / error / partial / stale；不用 0 顶替 |
| 图表 | 默认少而准；高级指标折叠；图表涨跌色与文字涨跌色同源 |
| 导航 | 一级 5 组，每组不超过 6 项；详情页从上下文进入 |

## 八、AI 时代差异化

### 8.1 不做通用聊天

通用聊天没有壁垒：用户可以直接用任意大模型。差异化在“模型看不到的东西”：

| 层 | 内容 | 壁垒 |
| --- | --- | --- |
| 数据层 | 点时间（point-in-time）财务、估值、行情、事件 | 中；可被复制，但清洗与对齐成本高 |
| 证据层 | 每个结论绑定数据块、日期、口径、样本数 | 高；需要工程与产品共同约束 |
| 记忆层 | 用户的观点、笔记、复盘、证伪历史 | 最高；越用越厚，迁移成本高 |
| 评估层 | 幻觉率、引用覆盖率、结论可复现性 | 高；需要长期测试集与红队 |

### 8.2 六个 AI 能力，按优先级

| 优先级 | 能力 | 输入 | 输出 | 验收 |
| --- | --- | --- | --- | --- |
| P0 | 公司一页纸摘要 | 公司数据、财务、估值、产业、事件 | 五段式摘要，每段带证据 | 每个数字可点回来源；无数据时明确不判断 |
| P0 | 财报变化三句话 | 最近 4–8 期财报 | 收入/利润/现金流/毛利率变化与原因 | 同比口径正确，不编造原因 |
| P1 | 多空对照 | 当前数据 + 研报 + 资金 | 多方论据、空方论据、关键分歧 | 每方至少 2 条证据，标明来源 |
| P1 | 事件历史类比 | 当前事件 + 历史同类事件 | 过去相似事件后的表现分布 | 样本数、时间窗、市场环境说明 |
| P2 | 观点检查 | 用户观点卡 + 最新数据 | 逻辑漏洞、被忽略的反例 | 不替用户改结论，只提问与列证据 |
| P2 | 组合暴露解释 | 持仓 + 行业 + 因子 | 集中度、风格暴露、风险来源 | 与风险引擎数值一致 |

### 8.3 证据边界

| 规则 | 实现 |
| --- | --- |
| 无数据不分析 | dataSource=unavailable 时，AI 只输出“缺少哪些数据、无法判断” |
| 每个结论带日期 | 引用块显示 `asOf`；过期数据标 stale |
| 区分事实与推断 | 事实用数据句，推断用“可能/倾向于”，并列出依据 |
| 不做投资建议 | 输出研究框架与证据，不给买卖指令；固定免责声明 |
| 可复现 | 同一输入与提示词，输出结构稳定；关键数值由代码计算，不让模型算 |

### 8.4 先修 AI 后端

当前 `/api/ai/diagnose` 因 `DEEPSEEK_API_KEY` 未配置返回 unavailable；`/api/ai/gems`、`/api/ai/strategy-recommend` 线上 404。产品转向 AI 研究助手之前，必须先做三件事：

一、配置并验证模型 Key，建立超时、重试、降级与成本上限。
二、把 AI 输出改成结构化 JSON（结论、证据、日期、置信度），前端按结构渲染，不解析自由文本。
三、建立离线评测集：至少 50 家公司 × 10 个问题，测引用覆盖率、数值错误率、无数据拒答率。没有评测，不上线。

## 九、商业化与渠道

### 9.1 收入结构

| 层级 | 目标用户 | 内容 | 价格假设 |
| --- | --- | --- | --- |
| 免费 | 尝鲜、轻度跟踪 | 延迟行情、基础自选、每月 3 次 AI 深度研究 | 0 |
| Pro | 核心个人用户 | 研究 workspace、观点卡、无限笔记、AI 深度研究额度、导出、提醒 | 39–99 元/月，按实验定价 |
| Team | 小机构/工作室 | 共享研究库、权限、评论、组合视图 | 299 元/月起，按席位 |

AI 成本必须单独核算：深度研究按“公司×问题”计费，设置每月额度与超额购买；不能用无限 AI 拉低毛利。

### 9.2 小程序

小程序不做完整终端，做三个高频场景：

| 场景 | 页面 | 价值 |
| --- | --- | --- |
| 今日简报 | 今日 | 3 分钟看完市场与自选异动 |
| 公司速览 | 公司一页纸精简版 | 看到线索后快速判断是否值得深挖 |
| 观点与提醒 | 我的研究 | 看自己的观点、收到证伪提醒 |

技术路径：Taro 4 复用 React 组件；SSE 用 `enableChunked`；微信登录与支付；研究内容分享卡。现有评估文档 `design/miniprogram-migration-assessment.md` 已给出 MVP 6 页与合规风险，可作为底稿。

商业化路径：免费内容/分享卡获客 → 小程序轻研究 → Web Pro 深度研究。小程序是渠道与提醒，不是主工作台。

### 9.3 合规

| 风险 | 处置 |
| --- | --- |
| 被视为投资建议 | 不做买卖点推荐；输出证据与研究框架；固定免责声明；不承诺收益 |
| 数据授权 | 只用公开数据与已授权接口；标注来源；不转售原始数据 |
| AI 生成内容 | 标注 AI 生成、人工可复核、可申诉；保留生成记录 |
| 小程序审核 | 金融类目资质前置确认；避免“荐股”“涨停预测”等表述 |

## 十、过渡路线

| 阶段 | 周期 | 内容 | 退出条件 |
| --- | --- | --- | --- |
| P0 基线与诚实 | 1–2 周 | `DESIGN.md` 评审；修 H1–H4；三页试点；token 缺口补齐 | 三页验收通过；无假数据；回归绿 |
| P1 研究工作台 MVP | 3–4 周 | 公司一页纸、今日简报、观点卡、笔记挂个股、自选挂观点 | 10 名内部用户完成一次完整研究闭环 |
| P2 产业与 AI 证据 | 4–6 周 | 产业/同业互链、研报链个股、AI 结构化输出与评测、图表简化 | 引用覆盖率 ≥90%；无数据拒答率 100% |
| P3 渠道与付费 | 4 周 | 小程序 MVP、Pro 付费实验、分享卡 | 付费转化与留存达到预设门槛 |

### 10.1 现在停止做的事

一、停止新增一级页面与导航项；新需求先进现有页面或观点卡。

二、停止新增指标与图表；除非能回答一个具体研究问题。

三、停止用演示数据或 0 值补空态；先修诚实缺陷。

四、停止把 AI 当聊天入口；AI 必须嵌入具体研究动作。

### 10.2 迁移原则

一、不删现有页面，先改入口与聚合，降低回归风险。

二、复用现有接口：估值、财务、K 线、资金、研报、产业都已真实可用，MVP 不新建数据源。

三、观点卡先本地存储，验证使用频率后再上后端与多端同步。

四、每个阶段独立可回滚；不以“大改版”一次上线。

## 十一、指标与风险

### 11.1 指标

### 11.2 风险与反对意见

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 数据广度陷阱 | 继续和终端比数据全，永远追不上 | 明确“研究深度优先”，行情只做上下文 |
| AI 幻觉 | 错误结论伤害信任 | 证据绑定、数值代码算、离线评测、无数据拒答 |
| 上游不稳定 | Key 未配置、接口 404 | P0 先修 AI 后端；每个 AI 功能有降级态 |
| 合规 | 被视为荐股 | 不做买卖指令；免责声明；审核前置 |
| 范围失控 | 31 页维护 + 新研究工作台 | 冻结新页面；先合并入口；按阶段交付 |
| 用户不买账 | 个人投资者可能只想看盘 | 首页保留行情；用试点验证研究闭环使用率 |
| 内容版权 | 研报摘要与转载 | 只做摘要与链接；不全文转载；标注来源 |

### 11.3 停止条件

一、P1 上线 4 周后，创建观点卡的用户比例低于 20%，暂停扩张，回到用户访谈。
二、AI 成本超过 Pro 收入 30%，先降额度与模型成本，不继续免费扩张。
三、合规评估不通过，暂停小程序与分享卡，只保留 Web 研究工具。

## 十二、决策请求

一、是否确认“研究工作台优先、行情为上下文”的方向，替代“继续扩页面/指标”。

二、是否批准 P0（设计基线 + 诚实缺陷 + 三页试点）立即执行；P1 在 P0 验收后启动。

四、是否同意小程序延后到 P3，先验证 Web 研究闭环与付费意愿。

五、是否接受“不删除现有页面、先改入口与聚合”的低风险迁移方式。
