# 缓存策略设计模式

## 设计目标
为A股行情分析系统提供高效、可预测的缓存层，减少API调用和数据库查询。

## 核心模式

### 1. LRU (Least Recently Used) 缓存
- **场景**: 热门股票行情、常用API响应
- **特点**: O(1) 查找/插入，自动淘汰最久未使用条目
- **容量**: 根据内存预算设定（推荐 1000-5000 条）

### 2. TTL (Time-To-Live) 缓存
- **场景**: 行情数据（30秒TTL）、K线数据（5分钟TTL）、财务数据（1天TTL）
- **特点**: 基于时间自动过期，适合时效性数据
- **实现**: 后台定期清理 + 读取时懒惰删除

### 3. Cache-Aside (旁路缓存)
```
读取流程:
1. 查询缓存 → 命中则返回
2. 未命中 → 查询数据库
3. 写入缓存 → 返回数据

写入流程:
1. 更新数据库
2. 删除/更新缓存
```

### 4. Write-Behind (写回)
- **场景**: 用户操作日志、搜索历史
- **特点**: 先写缓存，异步批量写数据库
- **风险**: 需要缓冲区持久化策略

### 5. 缓存键模式
```
stock:{symbol}          → 股票基础信息
kline:{symbol}:{period} → K线数据
quote:{symbol}          → 实时行情
search:{hash}           → 搜索结果
user:{id}:watchlist     → 用户自选股
```

### 6. 缓存失效策略
- **按模式失效**: `stock:*` 清除所有股票缓存
- **按前缀失效**: `kline:600519:*` 清除某只股票所有周期
- **定时全量刷新**: 每日收盘后清除所有行情缓存

## 性能指标
| 缓存层 | 命中延迟 | 容量 | 适用场景 |
|--------|---------|------|---------|
| 内存缓存 | <1ms | 有限 | 热点数据 |
| Redis | <5ms | 大 | 分布式缓存 |
| CDN | <20ms | 极大 | 静态资源 |

## 最佳实践
1. 行情数据 TTL 不超过30秒
2. 避免缓存穿透（布隆过滤器预检查）
3. 缓存雪崩保护（随机TTL抖动）
4. 热key检测与本地缓存提升
