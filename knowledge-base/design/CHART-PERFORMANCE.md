# 图表性能优化策略

## 问题

A 股行情数据量大：一只股票日 K 线 10 年约 2400 条，分钟级数据可能达数万条。大量数据直接渲染会导致：
- 图表卡顿（主线程阻塞）
- 内存飙升
- 交互响应慢

## 解决方案

### 1. 数据采样

#### LTTB 算法 (Largest Triangle Three Buckets)
- **原理**：将数据分成若干桶，每个桶中保留与相邻点构成最大三角形面积的点
- **优点**：视觉上与原始数据几乎一致，保留关键特征（峰值、谷值）
- **时间复杂度**：O(n)
- **适用**：K 线图、分时图降采样

```
原始数据 (5000点) → LTTB 采样 → 目标点数 (200点)
保留特征：峰值、谷值、趋势转折
```

#### 均匀采样
- 简单等距取点
- 适用：数据分布均匀的场景

#### 自适应采样
- 根据波动率分配采样密度
- 波动大的区域保留更多数据点
- 适用：分析图表（需要关注异常波动）

### 2. 虚拟化渲染

对于超过 2000 条数据的场景：
- 只渲染视口范围内的数据
- 滚动时动态加载/卸载
- 配合 LTTB 采样减少渲染量

### 3. 分块处理

大数据处理时避免阻塞主线程：

```typescript
// 每处理 1000 条数据让出主线程
for (let i = 0; i < data.length; i += 1000) {
  process(data.slice(i, i + 1000));
  await new Promise(r => setTimeout(r, 0)); // 让出
}
```

### 4. 性能监控

```typescript
// 渲染性能分析器
renderProfiler.measure('chart-render', () => {
  chart.setOption(option);
});
// 超过 16ms (60fps) 自动警告
```

## 性能基准

| 数据量 | 采样策略 | 目标点数 | 耗时 |
|--------|---------|---------|------|
| 5000 | LTTB | 200 | < 5ms |
| 10000 | LTTB | 500 | < 10ms |
| 50000 | LTTB | 500 | < 50ms |

## 最佳实践

1. **默认使用 LTTB** - 视觉效果最好
2. **超过 2000 点必须采样**
3. **K 线图默认显示 200 根**
4. **分钟级数据按需加载**（不一次性加载全部）
5. **分时图限制为 240 点**（4小时 × 60分钟）
