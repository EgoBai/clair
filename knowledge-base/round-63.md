## 解决方案

### 修复: 实现完整的 AlertsPage

**问题现象**: `/alerts` 路由显示"提醒页面正在开发中..."占位文本

**根本原因**: 页面组件未实现，仅保留了框架结构

**实现方案**:
1. **状态管理**: 使用 React useState + useCallback 管理规则和触发记录
2. **组件架构**:
   - `RuleCard`: 预警规则卡片，支持启用/停用/删除
   - `TriggerItem`: 触发历史项，支持确认操作
   - `StatCard`: 统计卡片面板
   - 创建规则模态框: 支持多种条件/字段/级别选择
3. **功能特性**:
   - 预警规则 CRUD (创建/读取/更新/删除)
   - 条件组合: 价格/成交量/涨跌幅 × 7种操作符 × 3种告警级别
   - 触发历史: 时间排序、确认机制、级别颜色标识
   - 统计面板: 活跃规则/今日触发/未确认/紧急告警
4. **UI 设计**: 参考 Linear/TradingView 的卡片式布局，清晰的信息层次

**代码量**: 从 11 行 → 400+ 行

**可迁移原则**:
- 对于"正在开发中"的空壳页面，优先检查是否有已存在的 utils/services 可以复用
- 组件拆分遵循单一职责: RuleCard 管规则展示、TriggerItem 管历史展示
- 状态提升原则: 规则和触发数据在页面级管理，子组件通过 props 接收
- 模态框点击外部关闭: 使用事件冒泡 + stopPropagation 防止穿透

## 对标分析

### TradingView Alert 系统的底层原理
- **条件评估引擎**: 支持实时数据流 + 历史数据回溯
- **频率控制**: 冷却时间机制防止重复触发
- **多渠道推送**: WebSocket + Push + Email + SMS
- **优先级队列**: 紧急告警优先处理

### Bloomberg Terminal 的告警系统
- **订阅模式**: 基于 Bloomberg 数据流的实时订阅
- **条件语言**: 支持复杂的布尔表达式组合
- **审计追踪**: 所有触发记录永久保存

### 可迁移的设计模式
1. **规则-触发分离**: 规则定义和触发记录独立管理，便于扩展
2. **级别颜色系统**: info/warning/critical 三级颜色编码，跨组件一致
3. **确认机制**: 未确认告警高亮显示，降低漏看风险
