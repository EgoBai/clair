## 第101轮自主循环：修复循环自身的「假绿验收」+ 终结连续11轮空转

**关键发现（结构性）**：项目是 Vite SPA，`curl -o /dev/null -w "%{http_code}"` 对任意路径恒返回 200（index.html fallback）。实测 `/definitely-not-a-route-xyz123` → 200。因此自主循环近百轮写进验收报告的「N 路由全 200（FAIL=0）」**对渲染健康零信息量**——页面白屏、组件抛错、路由根本没注册时 curl 依然全绿。属自欺型验收，约百轮未被发现。

**处置**：新建 `frontend/e2e/route-render-smoke.spec.ts`（32 例，141 行）
- 31 条 `ROUTE_PATHS` 路由（27 静态 + 4 参数化）× 四重断言：`.app-content` 可见 / `.content-wrapper` 非空（防白屏）/ 无 `pageerror` / 未落入 `UnifiedErrorBoundary`
- 1 条反向用例：不存在路由须渲染 `.not-found-page`，直接证伪 curl 假绿
- **反 404 退化守卫**：主理人写临时探针实测发现「404 页同样满足 content-wrapper 非空 + 无错误边界文案」→ 原断言对路由死链会漏网，遂补 `.not-found-page toHaveCount(0)`

**结论**：31 条路由首次有证据地确证真实渲染，零死链零白屏零崩溃。全量 e2e 52/52 零回归、tsc 0 错、guard 0/0/0、build 6.33s。

## 经验教训（可复用）

1. **curl 200 不能作为 SPA 路由健康证据**——SPA fallback 使其恒真。要验证渲染必须用浏览器级测试（Playwright）。这类「验证方法本身失效」的债比功能缺陷更隐蔽，因为它持续产出虚假的绿色信号。
2. **独立验证不止于复跑子智能体的测试**——还须构造反例探针，证伪其断言的甄别力。本轮正是靠探针才发现子智能体交付的测试对「路由退化为 404」漏网。已固化为协作纪律（PLAN 第五节 E5）。
3. **红线纪律需区分「活跃并行」与「陈旧遗留」**——单纯看 git status 有无脏源码会导致无限暂停（本项目连续 11 轮零产出）。加入 mtime + 跨轮 diff 稳定性判据后，可安全地在零交集文件域恢复推进。
